연구실 장비 예약 — 로컬 시험판 v2

1. 처음 실행하기 (Windows)
현재 이 PC에는 Node.js v22.17.1이 설치되어 있어 추가 설치가 필요 없습니다.
다른 PC에서는 https://nodejs.org 에서 Windows용 LTS 설치 파일을 받아 설치하세요.
필요 버전은 Node.js 22.13 이상입니다. 별도 SQLite 설치나 npm install은 필요 없습니다.

이 폴더 전체를 그대로 두고 실행.cmd를 더블클릭하세요.
실행 창이 열리고 기본 브라우저에서 http://127.0.0.1:8765 에 접속합니다.
자동으로 열리지 않으면 위 주소를 브라우저 주소창에 입력하세요.
실행 창은 사용하는 동안 열어 두세요. 외부 공개나 유료 서비스 가입은 없습니다.
HTML 파일만 더블클릭하면 작동하지 않습니다. 반드시 실행.cmd로 시작하세요.

2. 종료와 다시 실행
실행 창에서 Ctrl+C를 누르세요. 일괄 작업 종료 여부를 물으면 Y를 입력하세요.
예약은 자동 저장되어 별도 저장 버튼이 필요하지 않습니다(예약 창의 저장은 필요).
다음에는 실행.cmd를 다시 더블클릭하고 같은 주소로 접속하면 됩니다.
브라우저만 닫아도 서버는 실행 창이 열린 동안 계속 동작합니다.
이미 실행 중이라는 안내가 나오면 기존 실행 창을 사용하세요. 같은 서버를 두 번 켤 필요는 없습니다.

3. 예약하기
왼쪽 달력에서 날짜를 고르고 빈 시간 칸 또는 '새 예약'을 누르세요.
PC에서는 같은 장비의 빈 칸을 좌우로 드래그하면 선택 구간의 시작·종료 시간이 자동 입력됩니다.
눈금은 30분 간격을 유지하지만 드래그의 양쪽 끝은 5분 단위로 선택할 수 있습니다.
드래그 중 표시되는 실제 시간을 확인하세요. 1분 단위는 예약 창에 직접 입력하면 됩니다.
오른쪽에서 왼쪽으로 선택해도 됩니다. 휴대폰에서는 가로 스크롤과 칸 누르기를 사용하세요.
장비, 시작·종료 날짜와 시간, 예약자 이름을 입력하고 저장하세요. 제목·색상·메모는 선택 사항입니다.
예약자 이름과 실험 제목은 이전에 저장한 내용을 추천합니다. 각 항목 최근 50개의 서로 다른 값입니다.
제목을 비우면 예약 막대에는 이름만 표시됩니다. 취소한 예약의 입력 내용도 추천 이력에는 남습니다.
시간 입력칸 옆 화살표는 30분 간격 목록을 여는 기본 브라우저 버튼입니다.
시간은 24시간제이며 목록은 30분 간격입니다. 08:20 / 0820처럼 직접 입력해도 됩니다.
종료 시간 24:00은 해당 날짜의 다음 날 00:00으로 저장됩니다.
밤샘 실험은 종료 날짜를 다음 날로 지정하세요. 여러 날에 걸쳐 한 예약으로 저장됩니다.
막대의 ‹ / › 표시는 앞날부터 이어지거나 다음 날까지 이어짐을 뜻합니다.
기본 색상은 한 줄로 보이며, '기타 색상'을 누르면 사진을 참고한 8×8 팔레트가 열립니다.
색을 고르면 팔레트가 닫히고 현재 색상과 미리보기에 반영됩니다. 바깥 클릭이나 Esc로도 닫힙니다.
팔레트 아래 '직접 색상 지정'으로 원하는 색을 직접 선택할 수도 있습니다.
막대가 짧아 글자가 잘려도 마우스를 올리거나 클릭하면 전체 정보를 볼 수 있습니다.
예약 막대를 누르면 상세 조회·수정·취소가 가능합니다. 취소는 확인 창을 거칩니다.
PC에서는 예약 막대를 우클릭하면 수정·삭제 메뉴가 열립니다. 삭제는 확인 후 예약 취소로 처리합니다.
예약 막대를 왼쪽 버튼으로 잡아 옮기면 길이를 유지한 채 5분 단위로 이동할 위치를 선택합니다.
이동 전·후 장비와 시간을 확인한 다음 '이동 확인'을 눌러야 저장됩니다.
'취소' 또는 Esc를 누르면 변경하지 않습니다. 확인 후에도 겹치는 예약은 저장되지 않습니다.
다른 장비 행으로도 이동할 수 있습니다. 충돌하거나 사용할 수 없는 장비면 기존 예약을 유지합니다.
장비 배경은 한 줄씩 연보라색과 흰색이 번갈아 표시됩니다.
같은 장비에서 겹치는 시간은 거절됩니다. 앞 예약 종료와 다음 시작이 같으면 허용됩니다.
날짜와 시간은 PC 시간대 설정과 관계없이 Asia/Seoul(한국시간)로 처리합니다.

4. 장비 관리
초기 장비 32대가 들어 있습니다. 사진의 실명·실제 예약은 옮기지 않았습니다.
첫 실행일 기준 가상 예약 3개가 생기며 자유롭게 수정·취소할 수 있습니다.
'장비 관리 · 추가'에서 장비를 추가하거나 목록의 장비를 눌러 수정하세요.
장비 이름·종류·표시 순서·사용 여부·이용 안내를 저장할 수 있습니다.
위/아래 화살표는 즉시 순서를 바꿉니다. 순서 숫자가 같으면 등록된 순서대로 나옵니다.
사용 중지 시 새 예약은 막지만 기존 예약은 보존됩니다.
기존 예약이 있는 날에는 사용 중지 장비도 표시해 내용을 확인할 수 있습니다.
기타 중지 장비는 '사용 중지 장비도 보기'를 선택하면 보입니다.
이용 안내는 참고 문구입니다. XRD의 특정 요일/시간 등을 강제하는 기능은 아직 없습니다.

5. 저장 위치·백업·초기화
데이터 위치: 이 폴더의 data\lab-booking.sqlite
실행 중에는 lab-booking.sqlite-wal, lab-booking.sqlite-shm 파일도 생길 수 있습니다.
브라우저 저장소가 아니라 PC의 이 DB 파일에 예약과 장비 정보가 저장됩니다.
브라우저를 바꾸거나 새로고침해도 같은 로컬 서버의 데이터를 봅니다.
인터넷에 업로드하는 기능은 없습니다. 단, 현재 프로젝트는 OneDrive 폴더에 있으므로
PC의 기존 OneDrive 설정에 따라 파일이 동기화될 수 있습니다.
실제 운영 시험에는 폴더 전체를 C:\LabBooking 같은 OneDrive 밖의 폴더에 복사해 쓰는 것을 권합니다.
실행 중인 SQLite 파일을 여러 PC에서 OneDrive로 동시 공유하는 방식은 사용하지 마세요.

백업: 서버를 Ctrl+C로 종료한 뒤 data 폴더 전체를 다른 폴더에 복사하세요.
초기화: 서버 종료 → data 폴더 이름을 data-backup-날짜 등으로 변경 → 실행.cmd 재실행.
새 data 폴더와 초기 장비·가상 예약이 생성됩니다. 기존 데이터는 이름을 바꾼 폴더에 남습니다.
복구: 서버 종료 → 현재 data 폴더를 별도 이름으로 보관 → 백업 폴더 이름을 data로 변경 → 재실행.
기존 v1 브라우저 저장형 시제품은 backup\v1-before-sqlite.zip에 보관했습니다.
v1 예약은 새 DB로 자동 이전되지 않습니다.

6. 현재 구현 범위와 온라인 전환
로컬 시험용 · 사용자 인증 없음. 이름은 본인 확인 수단이 아닙니다.
이 화면을 사용하는 사람은 모든 예약을 수정·취소하고 장비 정보를 바꿀 수 있습니다.
현재 서버는 이 PC(127.0.0.1)에서만 접속됩니다. 휴대폰/다른 PC에서 이 주소로 접속할 수 없습니다.
모바일 폭에 맞춘 화면과 가로 스크롤은 있지만 외부 접속 기능은 아닙니다.
다른 창의 변경은 '새로고침' 버튼으로 다시 불러오세요. 오래된 예약 수정은 저장 시 거절됩니다.

나중에 온라인으로 전환할 때 연결·검증·운영 준비가 필요한 항목:
- 로그인/사용자 식별, 본인 예약 수정·취소 권한, 관리자 권한
- HTTPS 서버, 정기 백업, 장애 복구, 운영 로그
- 공유 온라인 DB와 서버·DB 차원의 동시 중복 예약 방지
지금도 로컬 SQLite 트랜잭션·DB 제약으로 겹침을 막지만, 온라인 DB로 바꾸면
그 DB에 맞는 동시성 제약과 여러 서버 환경의 검증이 필요합니다.
화면(dist), 통신(dist/api.js), 서버(server.cjs), 저장소(lib/repository.cjs)를 분리했습니다.
현재 비용: 이 프로그램 자체의 별도 서버/DB 사용료 없음. 유료 서비스 가입·배포 없음.
추가로 Cloudflare Pages + Supabase 전환용 코드와 SQL을 준비했습니다.
자세한 절차와 미검증 범위는 온라인전환안내.txt를 확인하세요.
이 온라인용 코드가 현재 로컬 실행에서 로그인·권한 관리가 활성화되었다는 뜻은 아닙니다.

7. 개발자용 실행과 검증
이 폴더의 터미널에서 node server.cjs 또는 npm start로 실행할 수도 있습니다.
npm test는 임시 DB로 검증하며 실제 data 폴더를 수정하지 않습니다.
검증결과.txt에 이번 확인 범위와 한계를 기록합니다.
고급 설정: LAB_BOOKING_PORT(기본 8765), LAB_BOOKING_DB(DB 경로),
LAB_BOOKING_SEED=0(완전히 빈 DB로 시작; 장비도 없음).
