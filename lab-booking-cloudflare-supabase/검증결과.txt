연구실 장비 예약 로컬 버전 — 검증 기록 (2026-10-13)

자동 검증: 17개 통과, 실패 0개
- 한국시간 변환, 직접 시간 입력, 24:00 처리, 날짜별 예약 표시
- 초기 장비 32대 및 가상 예시 예약
- 예약 등록·조회·수정·취소, 필수 항목과 잘못된 날짜·시간 안내
- 실험 제목을 비워 둔 예약 저장, 이전 예약자·제목 목록
- 같은 장비의 겹친 예약 거절, 맞닿은 시간 허용, 다른 장비 허용
- 자정을 넘는 예약과 여러 날 예약
- 수정 충돌, 오래된 수정 버전 거절, 취소 후 해당 시간 재예약
- 장비 추가·수정·순서·사용 중지
- 동시 예약 요청 중 하나만 저장, SQLite 제약으로 직접 중복 입력 거절
- 서버 재실행 후 데이터 유지
- 온라인용 파일 빌드 분리 및 비밀 키 사용 거절

브라우저에서 실제 조작하여 확인
- 색상 선택: 기본 색상 줄, '기타 색상' 클릭 시 8×8 팝업, 선택 후 닫힘
- 빈 칸 드래그: 00:55~03:05 선택 및 역방향 선택, 일반 클릭 예약
- 일반 예약·밤샘 예약·수정·중복 안내·확인 후 취소
- 장비 검색·종류 필터·관리 목록 및 가로 스크롤 중 장비명 고정
- 실험 제목 없이 저장, 저장한 이름·제목이 다음 입력 후보에 포함
- 기존 예약 우클릭 → 수정, 우클릭 → 삭제 → 취소 확인
- 기존 막대 드래그: 01:00~03:00 → 02:00~04:00
- 다른 장비로 이동하면서 02:05~04:05로 5분 조정, 예약 길이 유지
- 겹치는 시간으로 이동 시 충돌한 예약 시간 안내, 기존 예약 위치 유지
- 장비 한 줄마다 보라색/흰색 교차, 모든 줄 구분선 두께 동일
- 최신 기능 시험 중 브라우저 오류 로그 없음
- 이동 확인창 추가 후 별도 시험 DB에서 추가 확인:
  드래그 직후에는 기존 예약 유지, 취소 후 새로고침해도 미변경, Esc로 닫기,
  확인 후 다른 장비·시간으로 이동 및 새로고침 후 유지,
  겹친 시간으로 확인 시 오류 안내와 기존 예약 유지. 브라우저 오류 로그 없음.

실행 환경
- Windows의 Node.js 22.17.1 및 내장 SQLite 사용
- 실행.cmd 실행과 로컬 서버 재시작 확인
- 새 기능 UI 시험은 별도 시험 DB와 포트 8766에서 수행한 뒤 시험 서버 종료
- 실제 사용하는 데이터는 data/lab-booking.sqlite에 유지

검증 범위의 한계
- 모바일은 브라우저의 390×844 화면 크기로 확인했습니다. 실제 휴대폰 접속 시험은 하지 않았습니다.
- 현재 서버는 127.0.0.1에만 열려 있어 다른 PC나 휴대폰에서는 접속되지 않습니다.
- Cloudflare/Supabase 계정 생성·연결·배포는 하지 않았습니다.
- Supabase용 SQL, 로그인, 권한 규칙과 PostgreSQL 동시성 제약은 코드를 준비한 상태이며
  실제 Supabase/PostgreSQL 환경에서 실행 검증하지 않았습니다. 배포 전 별도 검증이 필요합니다.
- 로컬 SQLite의 중복 예약 방지와 재실행 후 저장은 위 검증에 포함됩니다.
- 현재 로컬 버전에는 실제 사용자 인증이나 본인 예약만 수정하는 권한 제한이 없습니다.
