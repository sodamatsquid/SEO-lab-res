예약 사이트 화면·엑셀 업데이트 — 2026-10-15

이미 운영 중인 로그인 없는 예약 사이트에 적용하는 수정 파일입니다.
이번 작업에서 실제 예약 데이터나 온라인 사이트는 변경하지 않았습니다.
배포와 아래 SQL 적용은 아직 하지 않았습니다.

1. 바뀐 사용 방법

PC: 예약 막대에 마우스를 올리면 이름·실험 조건·시작/종료·메모가 카드로 나옵니다.
클릭하여 수정, 우클릭하여 수정/삭제 메뉴를 여는 방식은 유지합니다.

모바일: 예약 막대 또는 예약 목록의 카드를 한 번 누르면 읽기 전용 상세 카드가 열립니다.
닫은 뒤 같은 예약을 약 0.55초 길게 누르면 수정/삭제 메뉴가 나옵니다.
손가락을 움직여 스크롤하거나 두 번째 손가락으로 확대하면 길게 누르기를 취소합니다.
삭제를 고른 뒤에도 확인 창을 거쳐야 취소됩니다.
시간표의 두 손가락 확대·축소와 드래그 예약 모드는 유지했습니다.

모바일 목록: [목록] → [조건별 보기]를 펼쳐 예약자와 장비를 고르세요.
하나만 골라도 되고 두 조건을 함께 적용할 수도 있습니다.
다시 접으면 선택 조건만 작게 보이고, [조건 초기화]로 전체 목록으로 돌아갑니다.
선택한 날짜의 예약을 조회합니다. 다른 날짜는 위 날짜 버튼으로 변경합니다.
기존 장비 검색·종류 필터도 적용 중이면 목록 위에 표시됩니다.
이 조회용 예약자 목록과 새 예약 창의 '내 최근 입력'은 별개입니다.

색상: 직접 선택한 최근 5개 색을 이 브라우저에 저장합니다.
새 예약에는 마지막 선택색을 적용하고, 기존 예약을 열 때는 그 예약의 색을 유지합니다.
다른 사람의 예약을 단순히 열어 봐도 내 기본색은 바뀌지 않습니다.
[비우기]는 최근 색상만 지웁니다. 실제 예약의 색은 바뀌지 않습니다.
다른 기기·브라우저와 동기화되지 않으며 사이트 데이터 삭제 시 초기화됩니다.

날짜: 위 입력칸에 20261015 또는 2026-10-15를 입력하고 Enter 또는 [이동]을 누르세요.
2026.10.15 / 2026/10/15도 가능합니다. 아래 달력 클릭은 그대로 사용할 수 있습니다.

엑셀: [기록 다운로드]에서 기간·예약자·장비 종류·개별 장비를 선택하세요.
장비 종류를 고르면 해당 종류의 장비만 선택창에 나옵니다.
정렬은 시작 날짜순 / 장비별 / 장비 종류별 중 선택합니다.
'예약기록' 한 시트에 정리하며 내부 ID·버전·등록/수정 시각 등 내부 정보 시트는 없습니다.
사용 시간은 정수 시간(h)과 나머지 분(min)으로 나눕니다. 예: 50분 → 0 / 50, 8시간 15분 → 8 / 15.
시작·종료는 한국시간이며 날짜 셀로 저장됩니다. 메모는 생략하지 않습니다.
아주 긴 메모는 셀을 선택하거나 행 높이를 늘려 전체를 읽을 수 있습니다.
제목행·장비/예약자 열 고정, 필터, 번갈아 표시되는 행 배경, 가로 인쇄 설정을 포함합니다.
이 파일은 예약 기록 보고서이며 계정·권한·DB 구조까지 복원하는 SQL 전체 백업은 아닙니다.

2. 온라인 사이트에 적용 — 순서대로 한 번

가. Supabase
압축을 푼 폴더의 supabase/06_export_categories.sql을 메모장으로 엽니다.
내용 전체를 복사합니다.
본인의 Supabase 예약 프로젝트 → SQL Editor → 새 쿼리에 붙여 넣고 Run을 누릅니다.
성공 표시를 확인합니다. 이 파일은 조회 함수만 추가하며 반복 실행도 가능합니다.
이미 로그인 없는 공개 예약판(03)이 적용된 사이트를 기준으로 합니다.
04·05나 장비 초기화 SQL을 다시 실행할 필요는 없습니다.
자동 삭제를 켜거나 끄는 SQL이 아닙니다. 기존 예약·회원·장비 행을 변경하지 않습니다.

나. GitHub
현재 사이트 저장소 SEO-lab-res에서 package.json이 보이는 폴더로 들어갑니다.
지금 구조가 그대로라면 lab-booking-cloudflare-supabase 폴더입니다.
[Add file → Upload files]에서 이번 압축 파일 안의 dist, lib, scripts, supabase 폴더와
server.cjs, 업데이트안내_20261015.txt를 함께 끌어 넣고 Commit changes를 누릅니다.
압축 파일 자체나 압축을 풀면서 생긴 바깥 폴더를 통째로 올리지 마세요.
예를 들어 기존 dist/app.js 위치에 새 dist/app.js가 올라가야 합니다.
기존 폴더를 삭제할 필요 없이 같은 경로의 파일을 덮어씁니다.
data 폴더, SQLite 파일, .env 파일은 올리거나 교체하지 않습니다.
이번 묶음에는 실제 예약 데이터와 API 키가 포함되어 있지 않습니다.

다. Cloudflare
GitHub에 연결한 기존 Pages 프로젝트의 자동 배포가 끝날 때까지 기다립니다.
기존 빌드 명령 npm run build:cloud, 출력 cloud-dist, 환경 변수는 유지합니다.
배포 성공 후 기존 사이트를 새로고침합니다. PC에서는 Ctrl+Shift+R을 사용할 수 있습니다.
색상 기억과 최근 입력은 해당 사이트 주소의 브라우저 저장소를 사용합니다.

새 UI는 보이는데 다운로드에서 '06_export_categories.sql' 안내가 뜨면
가 단계의 조회용 SQL이 같은 Supabase 프로젝트에 적용됐는지 확인하세요.
예약 조회·등록에는 이 새 다운로드 함수가 필요하지 않습니다.

3. 이 PC에서 로컬로 확인

프로젝트 원본 output/lab-booking-prototype에는 수정이 반영되어 있습니다.
기존 서버 창에서 Ctrl+C로 종료한 뒤 실행.cmd를 다시 실행하고 브라우저를 새로고침하세요.
로컬은 SQLite를 쓰므로 Supabase SQL을 실행할 필요가 없습니다.
기존 data/lab-booking.sqlite 파일을 그대로 두면 실제 예약이 유지됩니다.
다른 로컬 사본을 쓰는 경우 이번 수정 파일을 그 사본의 같은 경로에 덮어쓰세요.

자동 검사 42개 통과: 예약 등록·중복/경계·수정/취소·재실행 저장 유지,
날짜 입력, 색상 최근 5개/재사용, 길게 누르기 취소 로직,

실제 DB 대신 메모리 SQLite와 임시 PostgreSQL 환경에서 검사했습니다.

색상 새로고침 유지, 수정/삭제 확인 창, 종류+장비 조건의 실제 엑셀 다운로드 확인.

틀 고정/필터/인쇄 설정과 화면 미리보기 확인.
실제 휴대폰 기기의 길게 누르기·두 손가락 조작과 Microsoft Excel 앱 직접 열기는 미확인입니다.
엑셀 미리보기 도구는 이미지를 생성한 뒤 종료 오류가 있었으나, 생성된 화면과 파일 구조·값은 별도 검사했습니다.
온라인 Supabase SQL 실행, GitHub 업로드, 실제 운영 사이트에서의 동작은 아직 확인하지 않았습니다.
